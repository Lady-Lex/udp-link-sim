# M3 30 分钟长稳压测报告（实测数据）

## 1. 测试配置与 VM 环境条件

- **测试时间（UTC）**：`2026-11-25T11:55:35Z`（完整连续运行 1800 秒 = 30 分钟）
- **被测可执行文件**：打包单文件 `dist\UdpLinkSim.exe`（Windows x64，57.94 MB，SHA256 `ab8140ccf3369871e91365b661eda67423e5f189567fc7dc76fc343da045b1a5`）
- **VM 环境**：
  - 操作系统：Windows 10 Pro (`10.0.19045-SP0`, AMD64)
  - 虚拟化平台：Proxmox QEMU / EDK II 虚拟机
  - CPU / 内存：16 逻辑 vCPU，31.98 GB RAM
  - Python 运行时：3.14.6（内嵌于单文件包），`QueryPerformanceCounter` 分辨率 100 ns
- **拓扑与负载**：
  - **4 个共享绑定 UDP Socket / 8 条单向规则**（4 组全双工回环链路）
  - 固定延迟 `base_ms = 20.0`, `sigma_ms = 0.0`, `loss_pct = 0.0`
  - 稳态速率：每方向 **100 pps**，总计 **800 pps**，64 字节带魔数/方向/序号/时间戳负载，持续 1800 s（共 **1,440,000** 稳态包）
  - 单路突发：每 300 s 在方向 0 注入 200 包背靠背突发（共 5 次 = **1,000** 突发包）
  - GUI 并发活动：压测期间同步运行独立的 `UdpLinkSim.exe` GUI 实例（启用 250 ms 实时统计刷新）
  - 引擎定时配置：`win32_high_res_waitable` + `spin_us = 500`（经 A/B 实测选定的默认配置）

## 5. 长尾最大值说明（诚实记录）

- 在 30 分钟（144.1 万包）运行期间，8 个方向均出现了一次约 `48.7–56.8 ms` 的相关性调度长尾尖峰（E2E 对应 `69.1–77.4 ms`），这是非实时 Windows 10 虚拟机（Proxmox QEMU）在宿主机/OS 后台调度抢占下的典型单次停顿。
- 除该罕见 VM 调度尖峰外，**99.9% 的报文**调度偏差 ≤ `2.15 ms`，**99% 的报文**在全部 8 个方向上均 ≤ **`0.901 ms`**（中位数仅 `0.081 ms`），且全程零丢包、零错序、零端口/负载异常、内存平稳无泄漏。
