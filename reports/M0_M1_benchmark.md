## 测试环境（VM 条件）

- **操作系统**：Windows 10 Pro (`10.0.19045-SP0`, x64)
- **虚拟化环境**：Proxmox QEMU / EDK II 虚拟机
- **CPU / 内存**：16 逻辑 vCPU，31.98 GB RAM
- **Python / Qt / PyInstaller**：Python 3.14.6，PySide6 6.12.0，PyInstaller 6.22.3
- **高精度时钟**：`QueryPerformanceCounter`（单调，100 ns 分辨率）
- **被测目标**：打包单文件 `dist\UdpLinkSim.exe`（57.93 MB，无需管理员权限、无需驱动、无防火墙修改）

## 2. 定时器后端与有界自旋 A/B 实测（4 端口 / 8 方向，20 ms 固定延迟，100 pps/方向 = 800 pps，15 s）

数据来源：`reports/ab_benchmark.json`（每组发送 12,000 包，独立收发端点，64 B 负载）。

| 配置方案 | 定时器后端 | 自旋 (µs) | 全局 `send-deadline` p50 / p95 / p99 / max (ms) | 最差单路 P99 (ms) | 独立接收端 E2E p50 / p99 (ms) | 引擎 CPU (单核%) | 最大 RSS (MB) | 丢包/错序/错源端口 |
|---|---|---:|---|---:|---|---:|---:|---|
| `fallback_1ms_spin0` | `win32_legacy_waitable_1ms` | 0 | 0.485 / 0.998 / 1.307 / 8.438 | 1.425 | 20.782 / 21.785 | 7.77% | 29.54 | 0 / 0 / 0 |
| `highres_spin0` | `win32_high_res_waitable` | 0 | 0.494 / 0.972 / 1.302 / 4.523 | 1.400 | 20.777 / 21.704 | 8.59% | 29.36 | 0 / 0 / 0 |
| `highres_spin250us` | `win32_high_res_waitable` | 250 | 0.229 / 0.801 / 1.048 / 4.870 | 1.234 | 20.537 / 21.493 | 9.75% | 29.52 | 0 / 0 / 0 |
| `highres_spin500us` | `win32_high_res_waitable` | 500 | **0.086 / 0.569 / 0.836 / 3.588** | **0.961** | **20.433 / 21.289** | 14.08% | 29.15 | 0 / 0 / 0 |

### A/B 结论

1. 相比 1ms 传统回退定时器，Windows 高分辨率可等待定时器（`CREATE_WAITABLE_TIMER_HIGH_RESOLUTION`）在几乎相同的 CPU 开销下（8.59% vs 7.77%）将最大调度偏差从 8.438 ms 降至 4.523 ms。
2. 启用 500 µs 有界自旋（自旋循环内调用 `WaitForSingleObject(wake, 0)`，释放 GIL 并即时响应更早报文唤醒）后：
   - p50 偏差从 0.494 ms 降至 **0.086 ms**（提升 5.7 倍）；
   - 最差单路 P99 偏差从 1.400 ms 降至 **0.961 ms**（全部 8 路均低于 1 ms 期望目标，最高单路 0.961 ms，最低 0.682 ms）；
   - 引擎 CPU 仅增加约 5.5% 单核（14.08% 单核，折合 16 vCPU 整机 < 0.9%），无 GIL 饥饿。
3. 因此默认配置采纳 `spin_us=500`（仍可通过 `--spin-us 0` 关闭自旋以节省 CPU）。
